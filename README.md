# 奇异果 BI + AI 经营驾驶舱

本仓库 `aurax8040-debug/fmcg-kiwi-bi-cockpit` 的 `main` 是唯一主版本。所有功能修改都在此仓库的分支开发、验收后合并；不再在旧项目或副本同步修改。

## 启动

Mac 双击根目录的 `start-demo.command`，或在本目录运行：

```bash
python3 scripts/start-local-demo.py
```

默认启动不调用模型。Chrome打开本机8788端口，在「临促活动复盘」按需生成。已有 `.env` 保留在本机，不上传。原来的Dify Docker继续提供工作流和知识检索，它是运行依赖，不是另一份需要同步开发的BI项目。

需要一次真实联调时，明确使用 `--verify-ai`；可能消耗现有模型或检索额度，无自动重试。

## 唯一业务数据基线

140家门店、7个KA、15个SKU、2025-11至2026-10连续12个月，全部DEMO_MOCK。

| 文件 | 用途 |
| --- | --- |
| `demo-data/kiwi-bi-monthly.js` | BI月度汇总：25200条门店SKU月销售、1680条预算 |
| `demo-data/kiwi-promo-data.js` | 同店同活动的POS/TPM/SFA复盘：12场活动、840个参与组合 |
| 原始Excel和全年POS ZIP | 上述同一数据基线的原始输入，作为本机备份，不在每次启动时重生成 |
| Dify「佳农项目」3份文档 | 规范/SOP知识，不替代业务事实 |

以上不是多套竞争版本。旧20店样例与早期内置数据不再作为当前验收基线。旧页面脚本仍存在界面依赖，未拆除依赖前不能直接删除。

## 验收

```bash
npm test
python3 scripts/verify-history-run.py
```

历史校验只读取已有结果，不调用模型；支持后端已归一化answer和原始Dify analysis，失败返回非零退出码。所有引用先完整校验，再截断显示。

GitHub Pages托管静态大盘；真实AI需要本机后端或已配置公网后端。静态发布成功不等于AI后端已部署。

## 版本与清理

- 修复必须提交到本仓库；只维护一个本机工作目录。
- 旧目录先停止修改，作为历史备份。确认Dify挂载、原始数据与密钥已独立保留后，再决定清理；不自动删除。
- `.env`、密钥、`.ai-verification-*.json` 和临时备份不得提交。
- 不重复克隆项目来修同一个问题，不重生成模拟数据来解决界面或模型错误。
